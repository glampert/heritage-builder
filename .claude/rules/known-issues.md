# Known issues and unfinished work

Last verified against the code on 2026-11-12. Remove an entry once it's resolved.

The preset maps in `assets/configs/game/maps.json` are the debug presets until real custom maps exist.
- Campaigns II and III are in `assets/configs/game/campaigns.json` without missions, until game Phases 3 and 4 write them: finishing Campaign I reaches Campaign II, which the home menu and the campaign picker show as "coming soon" and can't start.
- Save headers (`crates/game/src/save_header.rs`) have no city name yet (missions don't name their cities; the Load / Save rows show the mission's name instead, and a custom game's map), and a game that's neither a campaign mission nor a custom game (a preset or new map from automation or the developer editor) is saved as Đại Long's. The Game menu names the mission and its campaign, or the custom game's map, where the mockups name the city (`TODO(realm-ui)` in `crates/game/src/menu/dialog/main_game.rs`). Saves made before headers show "—" in Load / Save and Continue's subline names only the save.
- Save thumbnails are desktop only: the web build keeps saves in localStorage and writes none, so its Load / Save preview is blank (`TODO(realm-ui)` at `save_thumbnail_path`) — `crates/engine/src/save/storage/mod.rs`.
- Some settings in the Settings dialog are stored only (`TODO(realm-ui)` at their configs): vertical sync and the frame rate limit (the backends and runners don't read them), mute in the background (the app backends don't report focus) — `crates/engine/src/config.rs`; colour-blind-safe overlays (M6/M7's overlays) and animated water (water has one frame) — `crates/game/src/config.rs` (`DisplayConfigs`). The UI scale scales the realm themes' text, the HUD's included, and the dialogs' sizes, but no other size in points: the HUD's panels and the minimap keep theirs, so at high scales the HUD's labels outgrow their panels (at 200% on 1280 × 720 the speed panel's "Paused" runs past its frame) until a full UI scale through egui's zoom lands (`TODO(realm-ui)` at `skin::ui_scale`). Key bindings are read-only and hard-coded where they act (`menu/dialog/settings/controls.rs`). The window mode, resolution and renderer rows show on the web too, where they don't apply — `crates/game/src/menu/dialog/settings/graphics.rs`.
- The main menus leave out some of the mockups' decoration: Kambara's vines over the panels, the blurred backdrop behind dialogs over the home menu, Home's last-played line, quote and distinctions, and italics (the realm fonts have no italic faces, so those lines are upright). Popups take the skin's popup heading, smaller than the game-quit mockups' and with a rule under it, and the Game menu's item under the Quit popup isn't drawn hovered as there — `crates/game/src/menu/dialog/`, `crates/game/src/menu/skin.rs`.
- Ambient sounds ignore game state; which sound plays is a placeholder (two TODOs) — `crates/game/src/system/ambient_sounds.rs`.
- Construction art is generic, by footprint size only. A site draws the same scaffold for every building of its size, and the renovation overlay is a scaffold around the house's front corner. - The fire watcher is the guard recoloured (`crates/tools/unit-recolor`) and the builder is a plain peasant; walker art of their own waits for the Blender walker experiment (placeholder-art Phase 6) — `docs/plans/city-risks.md`.

## Open bugs / design questions

- `ProducerBuilding` clears its stock as soon as it hands resources to a delivery unit, so the resources are lost if that unit fails to spawn. The TODO judges this low priority, since a spawn failure would itself be a bug — `crates/game/src/building/producer.rs`.
- House access to a service is decided by proximity to the service building, measured from the house's road-link tile, not by a service patrol unit actually visiting. A TODO asks whether to switch to visit-based access — `crates/game/src/building/house.rs`.

- Water shores are recomputed only when terrain is placed, so a save made before 2026-10-20, when the composed shore variations (channels, bays, several corners) were added, still draws plain water in a one-cell channel until the land next to it is placed again. Loading doesn't recompute them — `crates/game/src/session.rs`, see `.claude/rules/terrain-tiles.md`.

- In a MacOS `.app` bundle, `paths::base_path()` is `Contents/Resources`, the directory that holds `assets/`, so the game writes `saves/` (the user configs and the player's profile included), `cache/`, `logs/` and `screenshots/` inside the bundle. That fails or breaks the code signature for an installed app; they belong in `~/Library/Application Support` — `crates/engine/src/file_sys/desktop.rs` (`find_base_path`).

## Failure handling

- Save failures, autosave included, are only logged. `GameSession::save_game` returns `false`, but `GameSessionCmdQueue::cmd_save_game` discards that, so the player is never told — `crates/game/src/session.rs`. The Game menu's Save and quit sees its own save fail (`GameLoop::update_after_save`) and stays in the game, but says nothing either — `crates/game/src/game_loop.rs`.
- Load failures (unreadable file, save-version mismatch) are handled the same way: `load_save_game` logs and returns `false`, and `cmd_load_save_game` discards the result.
- Most other code treats unexpected state as fatal (`unwrap()`, `panic!`, asserts — several hundred call sites) rather than recovering.
